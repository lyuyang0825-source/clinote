# clinote

**中文病历结构化 + 可溯源质控。把自由文本变成“每个字段都能回看原文”的 SOAP，并在归档前跑一遍可解释的规则。**

> ⚠️ 本项目是文书辅助工具，**不是医疗器械**，不提供诊断、处方或治疗建议。任何输出都必须由有资质的医生逐条核对原文后签字使用。
>
> 这是四个行业独立仓库之一 · [总览与另外三个产品](https://github.com/lyuyang0825-source/ai-industry-labs)

## 为什么做这个方向

医生大量时间消耗在病历与行政事务上：AMA 2024 年调查显示医生平均每周工作 57.8 小时，其中间接诊疗 13 小时、行政事务 7.3 小时；22.5% 的医生每周在非工作时间使用 EHR 超过 8 小时。

但比“慢”更危险的是 AI 病历**写出没有发生的事**。一项儿科数字 scribe 抽查中，35 份 AI 病历至少 3 处严重错误：把“讨论过的检查”记成“已执行”、由“手/脚/嘴”误判手足口、漏记胸痛与焦虑。医生仍然要逐字校对，否则风险转嫁给患者。

所以这个产品的取舍是：**不追求一键成稿，追求“可核查的草稿”**。原文没写的字段标为未记录，规则命中必须给出理由与原文位置。

## 它做什么

| 层 | 做什么 | 产出 |
| --- | --- | --- |
| 结构化 | 段落切分 → 句子切分 → 生命体征 / 用药 / 诊断抽取 | SOAP JSON，字段带 `span` |
| 质控 | 11 条规则检查完整性、数值、矛盾、用药安全 | 分级问题清单（阻断 / 重要 / 提示） |
| 交付 | Markdown 报告 + JSON | 可直接贴回病历系统或给质控科 |

### 质控规则

| 规则 | 级别 | 检查内容 |
| --- | --- | --- |
| R001 | 阻断/重要 | 必填段落缺失（主诉、现病史、既往史、查体、诊断、处理） |
| R002 | 重要 | 胸痛/胸闷六要素不全（部位、性质、持续时间、诱因、缓解方式、伴随症状） |
| R003 | 阻断/重要 | 生命体征越界：BP≥180/110、SpO2<94 为阻断；BP≥140/90、HR 异常、发热为重要 |
| R004 | 阻断/重要/提示 | 用药缺剂量（阻断）、缺频次（重要）、缺疗程（提示） |
| R005 | 重要 | “待查/疑似”诊断没有对应检查或收住计划 |
| R006 | 提示 | 要求随诊/复诊但没写时间窗 |
| R007 | 重要 | 病史与诊断矛盾；自述血压控制值与实测差异过大 |
| R008 | 提示 | 未记录过敏史 |
| R009 | 重要 | 主诉缺少持续时间 |
| R010 | 重要 | 诊断高血压但处理段没有降压方案（会提示既往用药） |
| R011 | 提示 | 查体缺少生命体征 |

规则阈值集中在 `clinote/qc.py`，科室可以按自己的质控口径改。

### 一个容易踩的坑：否定症状

“无胸痛”不等于“胸痛”。R002 会跳过紧跟在“无 / 未见 / 否认 / 不伴 / 没有 / 未诉”之后的关键词，避免把阴性描述当成阳性症状去要求六要素。这个行为有单独的回归测试。

## 快速开始

无需第三方依赖，Python 3.10+：

```bash
git clone https://github.com/lyuyang0825-source/clinote.git
cd clinote

python3 -m clinote.cli --input samples/outpatient_zh_01.txt --out-dir demo_out --stdout
python3 -m unittest discover -s tests     # 12 tests
```

输出：

```
demo_out/outpatient_zh_01.json   # 结构化结果 + 问题清单 + 原文 span
demo_out/outpatient_zh_01.md     # 可直接阅读/归档的质控报告
```

## 三个样例，三种典型问题

| 样例 | 场景 | 结果 |
| --- | --- | --- |
| `outpatient_zh_01.txt` | 胸闷待查，表面规范 | 阻断 0 / 重要 3 / 提示 3（血压偏高、病史与实测不符、高血压无降压方案、用药无疗程、随诊无时间窗） |
| `outpatient_zh_02_bad.txt` | 故意写坏：缺段落、缺频次 | 正确报出必填段落缺失与用药频次缺失 |
| `outpatient_zh_03_followup.txt` | 高血压+糖尿病复诊 | 阻断 0 / 重要 1 / 提示 1（仅血压 172/104 超目标；用药缺疗程） |

`03` 是新增的“接近真实复诊”样例：主诉是头晕、现病史里写“无胸痛”，用来验证否定症状不会误触发 R002。

示例结论（`samples/outpatient_zh_01.txt`）：

```
阻断 0 / 重要 3 / 提示 3
- R003 血压 158/96mmHg 高于目标值
- R007 病史称控制于 130/80，本次实测 158/96
- R010 诊断高血压，但处理段没有降压方案（既往在用氨氯地平）
- R004 阿司匹林、阿托伐他汀均未写疗程
- R006 “心内科随诊”未写时间窗
```

## 输出示例（节选）

```json
{
  "summary": {"blocker": 0, "major": 3, "minor": 3, "verdict": "建议修改后归档"},
  "soap": {
    "S": [{"label": "主诉", "text": "反复胸闷3天。", "span": [4, 12]}],
    "O": [{"label": "体格检查", "text": "T 36.5℃ ...", "span": [153, 237]}]
  },
  "findings": [
    {"rule_id": "R003", "severity": "major", "title": "血压高于目标值", "span": [177, 190]}
  ]
}
```

`span` 是原文字符区间，前端可直接高亮；没有原文依据的字段不会被补写。

## 设计约束（有意为之）

- **只抽取，不补写**：没有“否认吸烟”就显示未记录，不会自动生成阴性病史。
- **每条结论可回看**：`span` 指向原文字符区间。
- **规则可解释**：没有黑箱打分，质控科能说清为什么拦。
- **纯标准库**：医院内网、离线环境可直接跑，不依赖模型服务。
- **既往用药与本次处方分开**，避免把“平时吃的降压药”算成本次医嘱。

## 当前限制

- 依赖 `【段落名】` 结构；完全自由排版的病历需要先做段落对齐。
- 仅覆盖中文成人门诊常见文书；儿科按体重给药、抗肿瘤方案、ICU 文书需要独立规则包。
- 未接入 ICD-10 / SNOMED 术语归一，诊断文本按原文保留。
- 规则是基线，不替代病案质控员的专业判断。

## 路线图

- [ ] 术语归一：ICD-10-CM / SNOMED CT / LOINC 映射
- [ ] FHIR `Composition` / `Observation` 导出，方便对接 HIS
- [ ] 语音转写接入（Whisper / 院内 ASR），保留时间戳对齐
- [ ] 科室规则包：心内、呼吸、儿科、急诊
- [ ] 审计日志：谁在什么时间改了哪个字段
- [ ] 可选 LLM 润色层：只允许改写措辞，字段与数值必须锁定原文
