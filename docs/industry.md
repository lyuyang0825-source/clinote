# 01 · 医疗：把“写病历”变成“查病历”

## 行业问题不是“打字慢”

AMA 2024 年医师执业调查的几个数字：

- 医生平均每周工作 **57.8 小时**，其中 **13 小时**花在间接诊疗（文书、沟通、协调）；
- **22.5%** 的医生每周在非工作时间使用 EHR 超过 **8 小时**；
- **43.2%** 的医生报告至少一种 burnout 症状。

但时间并不是最要命的。更危险的是 AI 病历“写没发生的事”：

- 某儿科数字 scribe 抽查 35 份 AI 生成病历，至少 3 处严重错误：把“讨论过的检查”记成“已执行”、把“手/脚/嘴”误判为手足口病、漏记胸痛与焦虑；
- EHR 交互占医生工作日 **43%–52%**，其中文书只占 **23%–30%**——大量时间其实花在查找、录入、回填、复制粘贴。

所以行业真正的缺口是：**结构化 + 可核查**。不是再生成一段更通顺的病历。

## 可被 AI 解决的产品方向

| 方向 | 解决什么 | 难度 | 本仓库 |
| --- | --- | --- | --- |
| 病历结构化与事实抽取 | 把自由文本变成可计算字段（症状、用药、检查、诊断） | 中 | ✅ clinote |
| 事前/事后质控 | 缺段落、剂量缺失、诊断无依据、随访无时间窗 | 中 | ✅ clinote |
| 智能随访与患者消息 | 复诊提醒、用药依从、术后随访问答 | 中高 | 路线图 |
| 医保/商保材料生成 | 按病种与条款组织证据链，减少退单 | 高 | 未做 |
| 临床科研数据抽取 | 从病历里抽变量、做队列筛选 | 高 | 未做 |

共同约束：**必须能指回原文**。医疗场景里“看起来对”比“明显错”更危险。

## clinote 的取舍

- 只做**抽取 + 规则质控**，不做诊断、不开药、不生成新事实；
- 每条问题都带 `span`（原文起止位置）与证据片段，医生能一眼核对；
- 11 条规则覆盖高频缺陷：必填段落、胸痛六要素、生命体征越界、用药缺剂量/频次/疗程、待查诊断无检查计划、随访无时间窗、病史与诊断矛盾、过敏史缺失、主诉无持续时间、高血压无降压方案、查体无生命体征；
- 分级：`blocker`（必须先改）/ `major`（重要）/ `minor`（提示），避免“几十条一起弹”导致告警疲劳。

示例输出（规范样例仍被查出 3 条重要问题）：

```
阻断 0 / 重要 3 / 提示 3
- R003 血压 158/96 超出诊室阈值
- R007 自述血压 130/80 与本次实测不符
- R010 诊断高血压但处理无降压方案
```

这正是产品的价值：**病历写得“通顺”不等于写得“完整、自洽、可执行”**。

## 怎么衡量

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 段落召回 | 必填段落识别召回 | ≥ 95% |
| 事实 F1 | 用药/诊断/生命体征抽取 | ≥ 0.85 |
| 问题精确率 | 报出的问题中被医生认可的比例 | ≥ 70%（低于此会被告警淹没） |
| 采纳率 | 医生实际修改的问题占比 | 上线后按周跟踪 |
| 单份耗时 | 从粘贴到处理完 | < 3s（本地规则） |

## 合规与边界

- **不是医疗器械**，不用于诊断/治疗决策；README 与 CLI 输出都明确声明。
- 数据最小化：只处理完成质控所需字段；不把病历用于训练；日志不落原文。
- 真实上线需：等保/数据安全评估、院内网部署、操作审计、医生复核签字。
- 生成式模型若接入，必须限制为“抽取/改写”，并对每个事实做原文一致性校验（NLI 或规则）。
